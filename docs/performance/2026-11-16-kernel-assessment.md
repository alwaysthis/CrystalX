# 成键搜索与材质生成评估（2026-11-16）

结论：值得分阶段迁移。先接入球体材质计算内核，收益已用独立 C++ 试验确认；其次迁移成键搜索，先保持现有算法及结果语义。此次只新增评估脚本和隔离试验，没有修改应用的生产调用路径。

## 测量条件

- 本机 Windows 11，Intel64 Family 6 Model 186 Stepping 2, GenuineIntel，Python 3.14.7 / Qt 6.12.0 / PyQt 6.12.0；C++ 试验为 MinGW GCC 14.2.0，C++17、-O3。
- 单进程依次测量，不与其他性能脚本并发；后台负载未受控制。每项通常 3 次，旋转 7 次，Python/C++ 材质各 15 次交替执行，表中均为中位数。
- 硅样本来自仓库 examples/Si.vasp，按固定密度扩为 8–4096 原子；额外覆盖倾斜晶胞、薄晶胞、四元素替换的合成样本。替换/剪切样本只用于覆盖性能路径，不代表物理合理的晶体。
- 原始全部样本和环境见 [2026-11-16-samples.json](2026-11-16-samples.json)。cProfile 另行运行，不把其显著的插桩开销混入表格。
- 4096 原子样本波动较大（成键三次为 739, 1179, 1277 ms），不能把单次结果或这里的增长比例当作严格复杂度/帧率保证。

**判断：数百至数千原子的打开、结构编辑或键规则应用已有可见等待，适合 C++。尚未编写或测量 C++ 成键实现，因此不承诺其加速倍数。** 可以先预编码元素对/阈值、减少重复字符串处理作为 Python 对照，避免将算法优化收益都归因于语言。

球体是固定 128×128，圆内有 12892 个着色样本。共享法线后，首次生成仍主要耗在逐像素 GGX/Smith 光照、线性到 sRGB 转换和 Python 通道循环。10000 次缓存命中是总耗时，不能与一个首次生成的耗时直接比较。

20 次参数变化是强制不同材质的计算负载，不能解释为实际拖动条每秒调用 20 次。颜色/材质组合增加时仍会有缓存未命中；缓存容量目前为 128 个球体、256 个雾化变体。雾化已经由 Qt 合成，不优先重写。

圆柱/箭头每次构造 33 个渐变色标，当前不缓存整个渐变；它和已缓存球体不同，可能影响每帧。建议先评估缓存颜色采样或批量计算色标，保留 Qt 画笔构造和绘制。

### 独立 C++ 球体试验

- 计算过程与现有公式一致，双精度，输出相同 BGRA / 预乘 ARGB32 格式；球内完全不透明、球外透明。
- 对粗糙度 0/.1/.35/.8/1、IOR 1/1.5/3、光泽 0/.35/1，共 45 组组合逐字节比较，最大通道差为 **0**。这里只验证固定蓝色与这组参数；生产接入仍需多颜色和随机参数覆盖。
- Python（不走图像缓存、法线已经共享）：**94.85 ms**。
- C++（含 ctypes 调用、输出缓冲区分配/转换及 QImage.copy）：**28.16 ms**。
- 本轮端到端约 **3.37 倍**；这是隔离材质生成的加速，不是整个软件或旋转的加速。初轮约 4 倍，交替采样复测约 3.4 倍，使用后者作为本报告结果。
- DLL 只保留在 ignored output，不由应用加载；不增加运行时依赖。试验不是最终扩展打包方案。

## 和实际视口的关系

900×700 离屏视口，包含默认键与方向轴，单色硅；setup 是第一次 set_structure，refresh 是相同 key 的刷新，cold 是清空材质缓存后的首帧，warm 是后续旋转。

| 原子数 | setup ms | 缓存搜索后的 refresh ms | 首帧 ms | 旋转 ms | 旋转新增球体材质数 |
|---:|---:|---:|---:|---:|---:|
| 8 | 15.94 | 3.28 | 161.42 | 21.14 | 0 |
| 512 | 242.84 | 36.85 | 245.53 | 116.58 | 0 |
| 4096 | 1640.63 | 314.01 | 868.54 | 788.47 | 0 |

三个规模旋转期间都未重新生成球体材质；旋转也不调用成键搜索。512 原子旋转 profile 中主耗时来自 paint_scene 的对象处理以及 QPainter.drawLine，此外有坐标变换、图像绘制和方向轴渐变。

因此迁移这两项能减少首次显示和编辑后的计算等待，**不会单独解决大结构旋转慢**。即使成键完全免费，4096 原子的缓存刷新仍有约 314 ms 的归一化/节点重建成本；旋转本身也有独立开销。此次不改变绘制后端。

## 建议的接入边界与验收

1. **球体材质优先**：C++ 输入 RGB、粗糙度、IOR、光泽，一次返回完整像素缓冲区；Qt 图像包装、材质缓存和雾化合成保留 Python/Qt。已有约 3.4 倍实测，是风险较小的第一步。
2. **成键第二**：一次传入行存储 3×3 晶格、N×3 分数坐标、元素整数 ID 和全部距离区间，批量返回笛卡尔键端点、源原子 ID 和实际匹配规则 ID。核心不依赖 Qt，输入归属和输出生命周期明确，不逐原子跨语言调用。
3. 初次迁移保持单线程及现有数值语义，先通过一致性测试，再考虑并行。生产绑定可使用 pybind11；纯计算段释放 GIL，不能在释放期间访问 Python 对象。释放 GIL 本身不会让同一 UI 线程上的同步调用变成后台任务；若需持续响应，应再把计算调度到工作线程。[官方说明](https://pybind11.readthedocs.io/en/stable/advanced/misc.html)
4. 保留 Python 参考实现/可用回退；无编译环境也能启动。构建与分发需覆盖支持的 Windows/Python 版本，不在用户首次启动时现场编译。
5. 成键结果按几何集合对比，验证周期自成键、倾斜/短晶胞、边界容差、多段距离、重合点、缺失规则、matched_ranges、原输入不变与去重。不能只比键数；端点变化可能影响键段编号及对象覆盖。
6. 材质需验证多种颜色、边界参数、球外 alpha、所有预设参数和缓存行为。当前试验仅球体；圆柱/方向轴尚无 C++ 性能或像素对照。
